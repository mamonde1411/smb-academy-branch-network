주소 규칙 · VLAN 배정 · 확장 시나리오


### 주소 규칙
`10.<거점>.<VLAN>.0/24` — 거점 1=본원, 2=도안 지점, 3~=향후 확장

# 어려웠던 점, 궁금했던 점과 답

**예를 들어 강사가 데스크톱을 사용할 때와 노트북을 사용할 때, 같은 Vlan 30에 허용 권한이 있는 것 인가, 아니면 유선 30 / 무선 35로 나누는가?**

생각해보자.
802.1X를 쓰기로 한 순간, 이 사람이 어느 매체로 접속했는지가 중요한가?
=> 아니다. 인증 결과로 VLAN이 정해진다면 유선이든 무선이든 상관 없어진다.

시각적으로 보면 같은 vlan에 둔 경우
유선: [데스크톱] ────────── [Access SW] ─────────────────────────> VLAN 20
무선: [노트북] ~~802.11~> [AP] ══════ CAPWAP 터널 (유선) ═══════> [WLC] ───────> VLAN 20

**그렇다면 나눴을 때와 나누지 않았을때의 장단점은 무엇인가?**

통합했을 때 (강사는 유선이든 무선이든 VLAN 30)

얻는 것 — VLAN·SVI·DHCP 풀·ACL이 절반이라 실수 여지가 줄고, "직무 = VLAN"이 깔끔해서 RADIUS 정책이 단순해집니다(계정 하나당 VLAN 하나). 사용자도 데스크톱에서든 노트북에서든 똑같이 동작하고요.

잃는 것 — 브로드캐스트 도메인이 커지고, 무선에만 다른 정책(대역폭 제한 같은)을 걸기 어렵고, 로그에서 IP만 봐서는 유선인지 무선인지 모릅니다.

나눴을 때 (유선 30 / 무선 35)

얻는 것 — 무선에만 별도 정책을 걸 수 있고, IP 대역만 봐도 접속 매체를 알 수 있어 트러블슈팅이 편하고, 무선 DHCP 임대 시간을 짧게 가져가는 식의 별도 관리가 됩니다.

잃는 것 — 모든 게 2배(VLAN, SVI, DHCP 풀, ACL). 그리고 RADIUS 정책이 복잡해집니다 — "이 사람은 VLAN 30"이 아니라 "이 사람이 유선이면 30, 무선이면 35"가 되니 조건이 하나 더 붙어요. 같은 사람이 기기를 바꾸면 IP 대역이 달라져서 혼란이 생길 수도 있고요.

직원 25명 규모에서는 "잃는 것"이 "얻는 것"보다 큽니다. 무선에만 걸 특별한 정책이 없고 브로드캐스트도 문제가 안 되는 크기니까요. 다만 결정은 하시고, 그 근거를 §3 탈락 기술 칸에 쓰세요. 면접에서 "왜 안 나눴나"는 충분히 나올 질문입니다.

**SSID 하나로 직무를 나눌 수 있나?**

802.1X + RADIUS를 사용하면 가능하다.
예를 들어, 강사와 도서 관리 직원이 노트북으로 접속을 한다면,
1. 노트북들이 SSID에 붙으려 함 (WPA2-Enterprise)
2. WLC가 "이 사람 누구야?"를 RADIUS에 물어봄
3. RADIUS가 계정을 확인하고 
강사 노트북엔 "통과, 이 사람은 VLAN 30"
도서 관리 노트북엔 "통과, 이 사람은 VLAN 20"
이라고 답함
4. WLC가 그 세션을 VLAN 20에 넣음

---

RADIUS는 응답에 통과/거부 + 통과 시 VLAN 번호도 같이 실어 보낼 수 있다.
이걸 Dynamic VLAN Assignment / AAA Override(Cisco WLC에서)라고 한다.
그래서 SSID는 직원용 1개, 게스트용 1개면 충분하다.
직무는 SSID가 아닌 802.1X+RADIUS를 사용한 계정으로 나눌거니까.


**왜 Port Security 대신 802.1X를 걸면 훨씬 강력할까?**

**학생 피드백 같은 경우 프런트와 강사 둘 다 접근이 가능해야하는데 그렇다면 VLAN 40 학생 피드백을 만들면 되나?**
아니다. VLAN은 사람을 묶는 그룹이다. 한 강사가 여러 VLAN에 속할 수는 없다.
결제DB, 도서DB, 수업자료, 학생 피드백 등은 서버존에 있게된다. 서버존의 피드백 자료에 대해 VLAN 30과 VLAN 10 둘 다 허용하면 된다. 그리고 그건 ACL로 처리 할 수 있다. 

VLAN     = 사람을 묶는 그룹        → 프런트(10) / 도서관리(20) / 강사(30)
서버존   = 자료가 있는 곳          → 결제DB, 도서DB, 수업자료, 학생피드백
ACL      = 누가 어느 자료에 닿는가  → 이게 둘을 연결하는 규칙
